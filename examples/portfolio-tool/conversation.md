# Example: Portfolio Tool Idea / 示例：项目作品集工具想法

## User / 用户

我是计算机专业学生，想做一个 AI 简历和作品集生成器。用户输入 GitHub repo 链接，工具自动分析代码，然后生成简历 bullet、项目介绍、面试回答。我想做成开源项目，目标用户是找实习的学生。我主要依赖 AI 编程，能做原型，但不确定能不能维护复杂后端和自动 repo 分析。

## Agent / 拷打官

方向有痛点，但你现在描述的是一个完整 SaaS，不是学生能轻松维护的开源 MVP。

先质疑条件：

1. GitHub repo 分析靠什么实现？你会处理不同语言、框架、monorepo、私有仓库吗？
2. 生成简历内容如果夸大事实，谁负责？如何保证“有证据”？
3. 目标用户为什么不用 ChatGPT 直接粘贴项目介绍？你比普通聊天强在哪里？

## User / 用户

我可以先不做自动抓 repo，让用户粘贴 README 或项目描述。重点是让 AI 帮他把项目讲清楚，不要吹牛。

## Agent / 拷打官

这就现实很多。你砍掉了最危险的部分：自动 repo 分析。

但还要继续砍：

- 不要做完整简历生成器，范围太大。
- 不要承诺“优化到最好”，标准不清。
- 先只做“项目经历证据化表达”。

MVP 核心路径：

> 找实习学生粘贴项目 README/描述，工具追问项目证据，然后输出 3 条不夸大的简历 bullet 和 5 个面试追问。

## User / 用户

这个可以。那它和普通 AI prompt 有什么区别？

## Agent / 拷打官

区别必须来自 workflow，而不是模型能力。

你要强制 agent 做三件事：

1. 先追问证据：用户做了什么、难点是什么、结果是什么。
2. 标记不可信表达：比如“提升性能 50%”没有证据就不能写。
3. 输出面试官可能追问，逼用户确认自己真懂。

如果没有这三点，它就是普通简历润色 prompt。

## Result / 结果

项目被压缩为：

> 一个 evidence-first portfolio workflow：让学生把项目经历讲清楚，不夸大，不代编，输出简历 bullet、项目故事和面试追问。
